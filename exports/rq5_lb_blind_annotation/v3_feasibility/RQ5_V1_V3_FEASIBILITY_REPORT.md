## Construct validity

The intended question requires three independently identifiable elements:

1. a genuine SE task,
2. referenced artifact R1,
3. a pinned snapshot where both can be evaluated.

Element (1) is missing for all 35 cases. Deriving a brief from the treated
instruction (v2) recreates circularity and cannot be used as a rescue.

Therefore the eligible set does **not** measure “material necessity for an
independently defined SE task.” It cannot support that construct.

---

## Selection effects

Exclusions are **not** random:

- **By design of RQ5 v1 selection:** cases were chosen as
  `born_stale` + `confirmed_false` documentary pairs with a **shared generic
  prompt**, not as tasks with external oracles.
- **By repository type:** content/skill packs and highly branded ecosystems are
  over-represented among re-identification risks; they never become eligible here
  because the oracle gate fails first.
- **By reference type / anchor length:** short anchors (`1/`, `2/`, `api/`) and
  package names were problematic for blinding in v2; under v3 they are moot until
  an independent task exists.
- **By experimental arm:** all candidates sit in the same born-stale pool;
  A/B/C are manipulations of instructions/paths, not alternate task oracles.
  There is **no** eligible arm-balanced annotation sample.

Do not describe these exclusions as MCAR.
